# المسلم V80.18 — نسخة جاهزة لملفات GitHub Pages

## رفع الموقع إلى GitHub
1. فك ضغط هذا الملف. ستجد `index.html` في جذر المجلد مباشرة، وليس داخل مجلد متداخل.
2. ارفع ملفات الواجهة إلى جذر مستودع الموقع: `index.html` و`media-api-config.js` و`manifest.webmanifest` و`qr-muslim-site.png` و`.nojekyll`.
3. **لا تحذف الملفات الموجودة أصلًا في مستودعك** مثل `supabase-config.js` أو `ai-config.js` أو الصور والملفات الأخرى. ارفع الملفات الجديدة فوق الملفات المطابقة فقط، واحتفظ بنسخة احتياطية من `index.html` القديم.
4. فعّل GitHub Pages من إعدادات المستودع إن لم يكن مفعّلًا.

## إصلاح مهم في اكتشاف الخادم
لم يعد الموقع يفترض أن نطاق GitHub Pages هو خادم معالجة. هذا الافتراض كان يوجّه الطلبات إلى عنوان خاطئ. كما أُصلح التعامل مع عنوان قديم محفوظ في المتصفح حتى لا يتغلب على العنوان الصحيح في ملف الإعدادات. بعد نشر خادم المعالجة، ضع عنوانه في `media-api-config.js` بدلًا من تركه فارغًا، مثل `window.MEDIA_API_BASE = 'https://your-service.onrender.com';` ثم ارفع الملف. ويمكن إدخال العنوان من إعدادات استوديو الصوت والفيديو أيضًا. لا يمكن معرفة عنوان خادم المعالجة من رابط يوتيوب أو من رابط الملف نفسه.

## لماذا خادم المعالجة منفصل؟
GitHub Pages يستضيف ملفات ثابتة ولا يشغّل Python أو FFmpeg أو نموذج فصل الصوت. لذلك لا يوجد ملف MySQL مطلوب، ولا يمكن تشغيل المعالجة الحقيقية من HTML وحده. استخدم حزمة الخادم المنفصلة `Muslim_V80_18_Media_Service_Backend.zip` على استضافة تدعم Docker/Python. بعد النشر، ضع عنوان الخدمة في `media-api-config.js`.

## تنبيه
فصل الموسيقى عن التلاوة آليًا ليس مثاليًا وقد يؤثر في بعض الأصوات. اختبر الناتج قبل استخدامه. الروابط الخارجية تعمل فقط إذا كانت متاحة ومسموحًا بتنزيلها؛ لا يتجاوز الخادم DRM أو قيود الوصول.

أُصلح وسمان HTML غير صالحين، وصُحّحت قائمة فهارس الآيات العالمية إلى 114 مدخلًا صحيحًا (مجموعها 6236 آية) لأنها كانت تحتوي على قيم زائدة وخاطئة قد تختار تسجيل آية أخرى. اجتازت سكربتات JavaScript المضمّنة فحص الصياغة، وفُحصت بنية ZIP ومعرّفات HTML المكررة. لم يتم اختبار فصل صوت فعلي على استضافة منشورة.
