# خادم معالجة الصوت والفيديو — المسلم V80.18

هذه الحزمة ليست جزءًا من ملفات الواجهة الثابتة. لا يوجد فيها MySQL ولا تحتاج قاعدة بيانات.

## النشر
1. ضع ملفات هذه الحزمة في مستودع مستقل أو مجلد `media-service` في مستودعك.
2. انشر الخدمة على استضافة تدعم Docker وFFmpeg وموارد كافية لنموذج Demucs، مع استخدام `render.yaml` أو إعداد Dockerfile.
3. انتظر نجاح البناء، ثم افتح `/health` على عنوان الخدمة؛ يجب أن يعرض `ok: true`.
4. من إعدادات الخدمة، انسخ قيمة `MEDIA_API_KEY` التي أنشأتها الاستضافة. في استوديو الموقع، افتح الإعدادات وأدخل عنوان الخدمة ومفتاح الوصول. ولتثبيت العنوان لكل الزوار، ضعه في `media-api-config.js` في مستودع الواجهة. **لا تضع مفتاح API داخل ملف JavaScript عام**؛ أدخله في إعدادات المتصفح أو استخدم طبقة وسيطة خاصة.

## متطلبات وتشغيل
- Python 3.11 داخل Docker، وFFmpeg.
- يحتاج Demucs إلى تنزيل أوزان النموذج عند أول تشغيل وذاكرة/مساحة كافيتين؛ قد تكون الخطة المجانية غير كافية.
- المسار `/health` لفحص الحالة، و`POST /api/process` للمعالجة، و`GET /api/files/<filename>` لتنزيل النتائج.
- لا تستخدم الخدمة لمعالجة محتوى لا تملك حق استخدامه، ولا تحاول تجاوز DRM أو تسجيل الدخول أو قيود المنصات.

## ملاحظة أمنية
قيمة `MEDIA_API_KEY` تحمي نقطة المعالجة من الطلبات غير المصرح بها. لا تنشر المفتاح في `media-api-config.js`؛ إذا كنت تحتاج واجهة عامة لجميع الزوار فالأفضل إضافة مصادقة وحدود استخدام/حجم ومعدل طلبات من خلال استضافة الخدمة.
